# Design review rubric

Use when the user shares a URL, screenshot, mockup, or component and asks for feedback — or before you present your own work. Go in this order; earlier items dominate later ones.

## 0. First five seconds (comprehension)
Run the five-second test literally: look at only the above-the-fold area for a few seconds, then look away and answer in one sentence each:
- What is this? Who is it for? What do I get?
- What is the single strongest piece of evidence, and is it visible yet? (a demo, "how it works", real logos, an accreditation, a number that matters)
If you can't answer, that's the #1 note. Nothing visual fixes an unclear value prop.
Then run the headline-skim test: read only the headings down the page. Does the story survive? Are headings claims or labels?

## 1. Trust check
Domain sensitivity: money, health, identity, security, kids → the bar for fit-and-finish is much higher; anything that reads "vibe-coded" or "hack project" costs conversions.
Ask: does anything here make me wonder "what else don't they pay attention to?" — misalignments, contrast errors, generic pill/gradient/glow, stock illustration mismatch, visuals that contradict the message.

## 2. Hierarchy and restraint
- Count type sizes and weights. Count cards, badges, icons, numbered markers, gradients. Anything over the anti-slop thresholds → note it with the specific fix (see `anti-slop-checklist.md`).
- Are supporting elements subordinate? Is there one signature moment, or noise everywhere?
- Is there anything you'd delete with no loss? List it.

## 3. What's working (say this explicitly)
Name the energy, idea, or element worth keeping — the international vibe, the QR-in-the-hero, the product animation. Reviews that only subtract produce dull results; the human's job is to protect the spark. If a cleanup would lose it, say what to keep.

## 4. Structure and flow
- Does the page get *more* convincing as you scroll? Then the hero is underperforming; pull the convincing parts up.
- Are sections claims (with proof) or generic labels ("Features")?
- Missing states: empty, loading, error, success. Missing responsiveness. Missing focus/keyboard.

## 4b. Funnel and CTA
One primary CTA per screen? Repeated with the same words down the page? Is the first ask proportional (try/watch vs book a demo)? What's behind the button — does the signup talk me out of it? What step came *before* this page (ad, post) and does it match? Anything behind tabs/carousels that must be seen?

## 5. Brand across touchpoints
If you can see more than one surface (site + product + email + docs), are they the same brand? Same type, spacing, tone, level of care? Consistency over time is what makes a brand trustworthy.

## 6. For products (not pages): walk the store
Use it as a first-time user would, on the real journey (email → site → product → first success). Friction-log every moment that feels weird; score red/yellow/green. Inspect as if something *is* wrong and you must find it: every word, every pixel, every state, every tap's response time.

## Output format for a review

Keep it conversational, prioritized, and concrete — like two designers talking over the screen, not a report:

1. **Take**: 1–2 sentences — what it is, whether it lands, the biggest thing in the way.
2. **Keep**: what's good and must survive any changes.
3. **Fix first** (max 3): each with *why* (which principle, which trust/comprehension effect) and *exactly what to do* (values, wording, deletions).
4. **Then**: 2–5 smaller refinements.
5. Offer to produce variations or a cleaned-up version if the environment allows.

Avoid long bulleted inventories of everything you noticed. Prioritize.
